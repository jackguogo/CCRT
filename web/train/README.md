# 认知训练模块（HS-CRT-01 · 体验版 web/train）

从 `领伯医汇/HS-CRT-01-体验版/web/train` 复制而来，用于本项目的训练方案演示与评审。
24 个训练方案 + 1 个方案库首页，纯静态、无后端依赖，双击即可运行。

## 运行方式

- 直接双击 `index.html`（file:// 已验证可用），或
- 起个静态服务：`python3 -m http.server 8080`，然后访问 `http://localhost:8080/`

浏览器需支持 Pointer Events 与 Canvas（Chrome / Edge / Safari 近两年版本均可）。
语音播报用浏览器内置 SpeechSynthesis，首次点击后才会出声；右上角 🔊 可静音。

## 目录结构

| 文件 | 内容 |
|---|---|
| `index.html` | 方案库首页，六大认知域 24 个方案卡片 |
| `CA-0x.html` | 复合性注意：信号捕捉 / 目标搜索 / 一心二用 / 快速切换 |
| `EX-0x.html` | 执行能力：色词辨析 / 智慧连线 / 宝塔规划 / 数字倒数 |
| `LM-0x.html` | 学习与记忆：数字传真 / 词海拾贝 / 图像配对 / 超市购物 |
| `LA-0x.html` | 语言：看图命名 / 词汇风暴 / 词图匹配 / 听指令行动 |
| `VP-0x.html` | 视结构：火眼金睛 / 巧手拼搭 / 空间旋转 / 妙笔临摹 |
| `SC-0x.html` | 社会认知：察言观色 / 心有灵犀 / 得体应对 / 言外之意 |

每个页面都是**自包含单文件**：样式、`Games` 训练引擎、关卡参数 `DATA` 全部内联。
24 个页面里的 `Games` 引擎是同一份代码的副本，改引擎要 24 个文件同步改（本次修复已同步）。

页面依赖 `patient.html` 的若干全局函数（`$`、`pad`、`HUD`、`TRAIN`、`API` 等）。
原文件把引擎抠出来单独成页时漏了几个，已在每个页面里补了一层兼容实现（见下）。

## 关卡与判定

- 每方案 10 关，参数表在页面底部 `<script>` 的 `DATA.levels` 里，逐关差异化（刺激间隔、目标比例、序列长度、限时……）。
- 自适应规则：正确率 ≥80% 且限时达标 → 升 1 关；连续 2 关优秀 → 跳 1 关；同关 3 次未通过 → 降 1 关（第 1 关保底）。
- 体验版把服务端 `/train/result` 的判定逻辑内联成前端模拟（`window.API.post`），结算页会标注"正式版在服务端结算"。

## 验证方式

用 Playwright（chromium headless）跑了三轮：

1. **首屏冒烟**：24 个页面逐个加载 → 进关 → 开始训练，捕获 `pageerror` / console error，0 报错。
2. **自动试玩**：每页随机点击作答 45 步，覆盖结算页与「💡 提示」按钮，0 报错；结算页正常出分、升降关建议正常。
3. **定点交互**：EX-02 按序点圆（得分 5/5）、EX-03 移球（步数递增）、LA-02 输入词（合法计数/非法拒绝）、VP-04 描线（覆盖率判定生效）、file:// 直接打开可用。

## 还没做 / 已知限制

- 引擎在 24 个文件里各有一份副本，维护成本高；建议后续抽成 `games.js` 单文件 + 各页只留 `DATA`。
- 页面没有「返回方案库」入口，只能靠浏览器后退。
- EX-02 智慧连线的节点位置随机，个别情况下两个圆圈会挨得很近（不影响点击判定）。
- 训练结果不落库，刷新即清空；正式版需接 `/train/result` 与数据库。
- 关卡参数、题库、人脸表情均为演示用素材，注册申报时需临床顾问复核（量表版权、范式一致性）。
